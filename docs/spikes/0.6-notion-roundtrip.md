# Spike 0.6 — Notion round-trip fidelity

**Date:** 2026-08-21 · **Result:** FAIL for complex-page full replacement

Test target was a disposable duplicate containing two columns, a synced block, a callout, six
child-page references and five inline database references.

1. `notion-fetch` captured the page's `<content>` exactly.
2. `notion-update-page {command:"replace_content"}` wrote that same content back with
   `allow_deleting_content:false`.
3. A second fetch produced a different hash and removed an `<empty-block/>` plus whitespace.
4. Repeating the same round trip changed the content again, proving continued normalization rather
   than a one-time canonicalization.
5. Major structural references survived, but byte and block fidelity did not.

**Decision:** full-page `replace_content` is not an inverse for structurally rich pages. E6 may use
targeted inverses, and may use full replacement only for demonstrably simple pages. Otherwise the
write is journalled and marked not-undoable.

The same OAuth access token was sent read-only to `GET https://api.notion.com/v1/users/me` with
Notion API version `2025-09-03`; it returned `401 unauthorized: API token is invalid`. Nox therefore
cannot use the public REST API to archive/delete creations. Creations remain explicitly
not-undoable.

`notion-fetch self` exposed 28 tools on the test workspace. `query_data_sources` was
`available_with_limit`; `query_meeting_notes` was `upgrade_required`. These values are
workspace-specific, so production must continue discovering and gating them at runtime.
